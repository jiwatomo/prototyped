Catatan desain

  • Identifier memakai UUID string (36) agar mudah dipindah ke PostgreSQL; tidak ada auto-increment.
  • Satu tags dipakai bersama pengguna dan beasiswa; konteks disimpan di tabel relasi (user_tags.context, scholarship_tags.context), bukan tabel tag terpisah.
  • Nilai enum disimpan sebagai string (mis. verification_status) agar mudah dibaca; validasi dilakukan di service, bukan CHECK constraint.
  • Kolom JSON (*_json, value_json, evidence) menyimpan struktur fleksibel; tipe/rentang tetap divalidasi Pydantic sebelum disimpan.
  • Skema dibuat lewat Base.metadata.create_all saat startup/seed (tanpa migrasi Alembic); perubahan kolom memerlukan reset database demo.
  • Status pendaftaran (open/upcoming/closed/unknown) tidak disimpan — dihitung dari application_start/application_deadline.
  • user_tags dan scholarship_tags memakai unique gabungan agar satu tag tidak dobel pada konteks yang sama.
  • Sesi login menyimpan hash token, bukan token asli; reset kata sandi mencabut semua sesi pengguna.

Dibuat otomatis dari metadata SQLAlchemy (backend/app/models/entities.py) dan snapshot backend/app.db. Regenerasi dengan python docs/generate_db_design.py.
